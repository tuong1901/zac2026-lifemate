# Agent execution fixes on feat/batch-actions-eval

The observed organizer score is **34.73/100**, supplied by the user. The older
98.22 result in commit history is not treated as a leaderboard result or as
validation of this change. Baseline source: `f8ca57d`.

## Changes

- Preserve schema-declared optional arguments: fan speed, light color, alarm
  repeat/enabled, calendar title and query filters can encode explicit intent.
  Preserve empty arrays used to clear a value. Unknown schema fields are still
  removed, and `ToolEnv.validate` remains the final schema check.
- Deduplicate reads by tool **and arguments**, allowing queries for another
  city, date or filter. Deduplicate successful writes by exact arguments;
  separate messages/notes/recipients are no longer suppressed by tool name.
- Reject malformed action envelopes and non-finite JSON numbers. Request a
  corrected plan within the existing step limit instead of executing a reference
  exemplar when generation cannot be parsed.
- Block tools outside the installed catalog before calling ToolEnv.
- Stop the remaining batch after a validation/execution failure and replan.
  Only successful calls enter the duplicate cache, permitting recovery after
  an explicit failed result. Exceptions are not automatically retried, because
  a lost response could follow a successful mutation.
- Do not truncate fractional integers or convert booleans into integer arguments.

## Evidence and limits

Run `python -m unittest discover -s tests -v`: **11 tests pass**, using synthetic
catalogs, requests and ToolEnv doubles. The regression suite fails on the original
V14 execution/guardrail files. `python scripts/check_compliance.py` also passes.
These checks establish the targeted execution behavior, not task accuracy or GPU
latency. Existing prompt heuristics and special-case tool branches remain;
this change is not an audit of all of them.

Preserving optional fields can also preserve an unwanted field generated by the
LLM; measure end-to-end behavior before claiming a score gain. Official ToolEnv,
full train/public metadata/catalogs and a running local LLM are not available in
this workspace. No new official evaluation or submission was produced. The
existing tracked `submission.jsonl` remains the old artifact. ASR, scoring and
submission-generation code are unchanged by this commit.
